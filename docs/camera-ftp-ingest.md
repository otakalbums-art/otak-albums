# Прийом фото з Wi-Fi камер по FTP

Один FTP-логін на клас — його вистачає на будь-яку кількість камер цього
класу одночасно. Кілька камер розводяться по категоріях не окремими
логінами, а різною **цільовою папкою (Directory)** в налаштуваннях FTP
кожної камери (детальніше — крок 3). Кожне фото, скинуте камерою, одразу
зʼявляється в галереї учнів класу (без ручного завантаження) — завдяки
вже наявній real-time підписці на нові фото
(`apps/client/app/gallery/page.tsx`).

## Вимоги

- Камера з Wi-Fi-модулем і **вбудованою підтримкою FTP-вивантаження**
  (типово в напів-профі/профі тілах: Canon EOS R/1D-series з бездротовим
  передавачем, Nikon Z8/Z9/D850+, Sony a7 IV/a9+...). Камери, у яких Wi-Fi
  уміє лише "передати на телефон через фірмовий додаток" (Canon Camera
  Connect, Nikon SnapBridge тощо, без прямого FTP) — цей спосіб не
  підійде, потрібен інший шлях імпорту.
- Комп'ютер з адмінкою і камера — в **одній Wi-Fi мережі**.
- FTP тут — простий, без шифрування (стандартна практика для закритої
  локальної мережі на зйомці; більшість камер FTPS/SFTP і не підтримують).

## Як це працює в мережі

```
📷 Камера  ──Wi-Fi──▶  🌐 Роутер/точка доступу  ──Wi-Fi──▶  💻 Ноутбук (адмінка + FTP-приймач)
                                                                    │
                                                                    ▼ (тільки тут інтернет)
                                                              ☁️ Supabase (Storage + БД)
```

Камера й ноутбук мають бути підключені до **однієї й тієї ж точки доступу**
— це звичайна локальна мережа (LAN), інтернет тут не бере участі. Камера
відкриває пряме TCP-з'єднання на локальну IP ноутбука (поле "Host" у
панелі — завжди показує актуальну адресу цього комп'ютера в поточній
мережі). Інтернет потрібен лише на другому кроці — коли приймач сам
вивантажує вже отримане фото в Supabase; сам зв'язок камера↔ноутбук працює
навіть без інтернету взагалі.

### ⚠️ Client isolation на venue-мережах

Багато шкільних/актових Wi-Fi мереж мають **client isolation** (ізоляцію
клієнтів) — пристрої в такій мережі бачать інтернет, але **не бачать одне
одного**. Камера технічно "в тій самій Wi-Fi", але фізично не достукається
до ноутбука — і жодні налаштування в коді цього не виправлять, це
обмеження на рівні роутера venue.

**Практична рекомендація:** возити свою власну точку доступу — портативний
travel-роутер або звичайний телефонний хотспот (саме такий діапазон,
`172.20.10.x`, був у нашому тесті) — і підключати до нього і ноутбук, і
камеру. Гарантовано без ізоляції клієнтів, і не залежиш від мережі
конкретного закладу.

## 1. Увімкни прийом

В адмінці → **«Прийом з камер (Wi-Fi)»** → перемикач "Прийом увімкнено/вимкнено"
вгорі сторінки. Кнопка сама піднімає окремий процес на сервері
(`apps/admin/scripts/ftp-ingest.mjs` через `apps/admin/lib/ftp-process-manager.ts`)
— термінал не потрібен.

Далі на тій самій сторінці, кнопками:
1. Обери клас
2. Обери, скільки камер підключаєш (1–5) — під кожну зʼявиться картка з
   готовими Host/Порт/Логін/Пароль/Папка й кнопкою "📋 Копіювати" на
   кожне поле (клацнув — вставив у меню камери, нічого виділяти вручну)

## 2. Налаштуй камеру (одноразово на клас/камеру)

⚠️ У майстрі підключення камера зазвичай спершу питає **спосіб з'єднання**
— обери варіант "приєднатися до мережі" / "select network" (камера
підключається як звичайний клієнт до наявного роутера). **Не** обирай
"камера як точка доступу" ("Camera access point mode") — той варіант
змушує камеру самій створювати окрему Wi-Fi мережу зі своїм SSID, і тоді
ноутбук з адмінкою до неї не достукається (він сидить в іншій мережі —
travel-роутері/хотспоті). Якщо в майстрі це проскочило — просто "Назад" і
обери мережу travel-роутера зі списку.

У меню камери (шлях залежить від моделі, зазвичай `Мережа` /
`Network` → `FTP-передача` / `FTP transfer`) — усі значення бери з картки
потрібної категорії на сторінці «Прийом з камер»:

| Поле | Звідки взяти |
|---|---|
| Host / Сервер | картка → "Host", кнопка 📋 |
| Порт | картка → "Порт" (типово `2121`, не стандартний 21) |
| Логін | картка → "Логін" — **той самий для всіх камер цього класу**, тепер це просто 6 цифр (набирати цифровим набором на камері швидше, ніж hex з буквами) |
| Пароль | картка → "Пароль" — так само спільний, теж 6 цифр |
| Режим | Пасивний (Passive / PASV) |
| Цільова папка | картка → "Цільова папка (Directory)" — саме тут відрізняються різні камери одного класу |
| Автовивантаження | Увімкнути "вивантажувати кожен кадр одразу після зйомки" |

Це справді одноразово: Canon-камери запам'ятовують ці налаштування і самі
перепідключаються та вивантажують кадри щоразу при увімкненні Wi-Fi —
повторно вбивати SSID/host/логін не треба, поки клас не зміниться (новий
клас = новий логін/пароль, бо вони прив'язані до class_id).

Збережи налаштування, зроби тестовий кадр — за пару секунд він має
з'явитись і в галереї учнів класу, і лічильником "📸 N фото прийнято" на
сторінці «Прийом з камер».

## 3. Декілька камер в один клас — різні папки

Логін/пароль однакові для всіх камер класу — саме тому досить обрати
"скільки камер" один раз на кроці 1, а не заводити кожну окремо. Розводить
камери поле **Цільова папка (Directory / Target folder)**: назва підпапки
визначає категорію фото:

| Папка на камері (Directory) | Категорія фото |
|---|---|
| `/` (не вказувати взагалі) | Без категорії |
| `/portrait` | Портрети |
| `/group` | Групові |
| `/ceremony` | Церемонія |
| `/personal` | Персональні (без прив'язки до учня — приєднати можна пізніше вручну через адмінку) |

Підпапки вже існують заздалегідь (створюються автоматично при першому
підключенні класу) — камері не треба вміти створювати директорії, лише
зайти в уже наявну.

## 4. JPEG і RAW — окремі підпапки, автоматично

Приймач бере й JPEG, і RAW (`.cr2`/`.cr3`, `.nef`/`.nrw`, `.arw`/`.sr2`,
`.raf`, `.orf`, `.rw2`, `.pef`, `.srw`, `.x3f`, `.dng` — повний список у
`apps/admin/lib/file-type.ts`). Розводити їх вручну не треба: система сама
визначає тип за розширенням файлу й кладе кожен кадр у Storage за шляхом

```
{classId}/{категорія}/JPEG/…   -- .jpg/.jpeg
{classId}/{категорія}/RAW/…    -- усі RAW-формати
```

тобто підпапка `JPEG`/`RAW` з'являється всередині кожної категорійної
папки автоматично, без ручних дій фотографа — так само для ручного
завантаження через `/classes/[classId]/upload`.

Хто що бачить:
- **Учні** (`apps/client/app/gallery`) — лише JPEG, RAW відфільтровано на
  рівні API (`file_type = 'jpeg'`).
- **Адмін** — і JPEG, і RAW, у новій галереї `/classes/[classId]/photos`
  (кнопка "Переглянути фото" на сторінці «Класи та папки»). Кадри з
  однаковим базовим іменем файлу в межах категорії показані парою
  (JPEG-прев'ю + посилання завантажити RAW), навіть якщо камера пише їх
  за одну зйомку окремими файлами.

## Обмеження

- `personal` через FTP — без прив'язки до конкретного учня (набирати
  UUID учня в тісному меню камери нереалістично); за потреби прив'язати
  фото до учня можна пізніше вручну.
- Приймаються лише JPEG і RAW-розширення зі списку вище (перевіряються за
  розширенням; JPEG додатково звіряється за magic bytes файлу) — інше
  (HEIC, відео тощо) буде проігноровано.
- Термінальна команда `pnpm --filter admin run ftp:start` і далі працює
  напряму (для відлагодження) — але звичайний шлях тепер через перемикач.
